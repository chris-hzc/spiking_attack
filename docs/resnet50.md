# Testing ResNet50 with Spiking-PGD on CIFAR-10

Quick guide for testing ResNet50 with Spiking-PGD attack using pretrained models.

## 📋 Overview

This guide covers:
1. Setting up a pretrained ResNet50 model
2. Running Spiking-PGD attack evaluation
3. Analyzing results

## 🚀 Quick Start (3 Steps)

### Step 1: Prepare Pretrained Model (2 minutes)

```bash
# Option A: Create a test checkpoint (for script testing only)
python download_pretrained_resnet50.py

# Option B: Use your own pretrained checkpoint
# Place your checkpoint in: checkpoint_resnet50/your_model.pth
```

⚠️ **Important**: The auto-generated checkpoint is randomly initialized. For meaningful results, use an actual pretrained model.

### Step 2: Run Single Test (1 minute)

```bash
# Test with default settings (rho=0.02, epsilon=8/255, 20 steps)
python test_resnet50_spiking.py \
    --checkpoint checkpoint_resnet50/resnet50_random.pth \
    --rho 0.02 \
    --steps 20 \
    --num_samples 1000
```

### Step 3: Run Full Experiments (10-30 minutes)

```bash
# Test multiple configurations automatically
bash scripts/run_resnet50_experiments.sh checkpoint_resnet50/resnet50_random.pth
```

## 📖 Detailed Usage

### Main Script: `test_resnet50_spiking.py`

**Required Arguments:**
- `--checkpoint`: Path to pretrained ResNet50 checkpoint

**Key Optional Arguments:**
- `--rho`: Threshold for adaptive reuse (default: 0.02)
- `--epsilon`: Attack budget in [0,255] (default: 8)
- `--steps`: Number of attack iterations (default: 20)
- `--num_samples`: Limit test samples (default: 10000)
- `--verbose`: Print detailed per-batch info
- `--save_log`: Save results to log file

**Example Commands:**

```bash
# Basic test on 1000 samples
python test_resnet50_spiking.py \
    --checkpoint /path/to/model.pth \
    --rho 0.02 \
    --num_samples 1000

# Full test with logging
python test_resnet50_spiking.py \
    --checkpoint /path/to/model.pth \
    --rho 0.02 \
    --save_log

# High efficiency test (more reuse)
python test_resnet50_spiking.py \
    --checkpoint /path/to/model.pth \
    --rho 0.03 \
    --steps 20

# Strong attack test
python test_resnet50_spiking.py \
    --checkpoint /path/to/model.pth \
    --rho 0.02 \
    --epsilon 16 \
    --steps 50

# Verbose output
python test_resnet50_spiking.py \
    --checkpoint /path/to/model.pth \
    --rho 0.02 \
    --verbose
```

## 🔧 Checkpoint Formats

The script supports multiple checkpoint formats:

**Format 1: Dictionary with 'net' key** (preferred)
```python
checkpoint = {
    'net': model.state_dict(),
    'acc': 85.23,  # optional
    'epoch': 150    # optional
}
```

**Format 2: Dictionary with 'state_dict' key**
```python
checkpoint = {
    'state_dict': model.state_dict()
}
```

**Format 3: Direct state_dict**
```python
checkpoint = model.state_dict()
```

## 📈 Understanding Results

### Benign Accuracy
Accuracy on clean (unperturbed) images. Should match your model's standard test accuracy.

### Robust Accuracy
Accuracy on adversarial images generated by Spiking-PGD. Lower = attack is more successful.

### Attack Success Rate
Percentage of samples where attack successfully changed the prediction.
```
Attack Success Rate = 100% - Robust Accuracy
```

### Average Precision
Percentage of full computations performed during attack.
- 100% = no computational savings (all layers computed at every iteration)
- 65% = 35% computational savings
- Lower precision = more cost reduction

### Layer-wise Precision
Shows which layers reuse activations more:
- Early layers: Often lower precision (more reuse) - changes less
- Later layers: Often higher precision (more computation) - changes more

## 🎯 Tuning Guide for ResNet50

### Choosing Threshold (rho)

| rho | Expected Precision | Use Case |
|-----|-------------------|----------|
| 0.01 | ~95% | Minimal savings, maximum attack strength |
| 0.02 | ~65% | **Recommended balance** |
| 0.03 | ~40% | High efficiency, good attack |
| 0.05 | ~20% | Very high efficiency |

**For ResNet50 (deeper network):**
- Can often use slightly higher rho than ResNet18
- Try 0.025-0.03 for good balance

### Computational Considerations

ResNet50 is significantly larger than ResNet18:
- More layers → more opportunities for reuse
- Deeper network → activations may change less in middle layers
- Longer runtime → savings more impactful

**Expected timings (RTX 3090, batch=100):**
- Standard PGD-20: ~1.2s per batch
- Spiking-PGD (rho=0.02): ~0.8s per batch
- Speedup: ~1.5×

## 🐛 Troubleshooting

### Issue: "Checkpoint not found"

**Solution:**
```bash
# Check file exists
ls -la checkpoint_resnet50/

# Create if missing
python download_pretrained_resnet50.py
```

### Issue: "RuntimeError: size mismatch"

**Cause:** Checkpoint is for different architecture or number of classes.

**Solution:**
- Ensure checkpoint is ResNet50 for CIFAR-10 (10 classes)
- Check checkpoint format matches expected format

### Issue: Out of memory

**Solution:**
```bash
# Reduce batch size
python test_resnet50_spiking.py \
    --checkpoint model.pth \
    --batch_size 50  # reduced from 100

# Or test fewer samples
python test_resnet50_spiking.py \
    --checkpoint model.pth \
    --num_samples 500
```

### Issue: Very slow execution

**Solution:**
1. Ensure CUDA is available: `torch.cuda.is_available()`
2. Reduce number of samples: `--num_samples 1000`
3. Use fewer attack steps: `--steps 10`

## 📊 Comparison: ResNet18 vs ResNet50

| Metric | ResNet18 | ResNet50 | Difference |
|--------|----------|----------|------------|
| Parameters | ~11M | ~25M | 2.3× larger |
| Layers | 18 | 50 | 2.8× deeper |
| FLOPs | ~0.5G | ~1.3G | 2.6× more |
| Typical Accuracy | 95% | 96% | +1% |
| Attack Time (PGD-20) | 0.5s | 1.2s | 2.4× slower |
| Spiking Savings | 30-40% | 30-40% | Similar |

**Key Insight:** ResNet50 benefits similarly from Spiking-PGD despite being larger!

## 💡 Tips for Best Results

1. **Use Real Pretrained Model**: Random weights give meaningless results
2. **Test on Subset First**: Use `--num_samples 1000` for quick iteration
3. **Save Logs**: Always use `--save_log` for experiments
4. **Compare Multiple rho**: Try 0.01, 0.02, 0.03 to find best trade-off
5. **Check Benign Accuracy**: Should match your model's normal accuracy
6. **Monitor Precision**: Layer-wise precision reveals architecture behavior
